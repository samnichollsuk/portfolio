## Development

When starting the dev server, use background mode:

```
bun run dev --background
```

Manage the background server with `bun run astro dev stop`, `bun run astro dev status`, and `bun run astro dev logs`.

## Coding standards

### Styling

- Style with [Tailwind CSS](https://tailwindcss.com) v4 utility classes in the markup. Don't add `<style>` blocks to components or pages.
- Tailwind is loaded through the `@tailwindcss/vite` plugin in `astro.config.mjs`. There is no `tailwind.config.js`: configuration lives in CSS.
- `src/styles/global.css` is the only stylesheet. It holds:
  - design tokens in `@theme` (colours, fonts), with dark-mode values overriding the same variables under `prefers-color-scheme: dark`;
  - base element styles in `@layer base` (headings, links, focus ring, reduced motion);
  - shared custom utilities defined with `@utility` (`wrapper`, `eyebrow`, `gradient-text`, `bg-brand-gradient`).
- Use the theme colours (`bg-bg`, `bg-surface`, `text-fg`, `text-muted`, `border-border`, `text-accent`, ...) rather than Tailwind's palette or hex values, so light and dark mode stay in sync. Add a new token to `@theme` (and its dark value) before using a new colour.
- Arbitrary values (`text-[clamp(...)]`) are fine for one-off fluid sizes. If the same value or class list is needed in several places, make it a `@utility` in `global.css`.
- Keep accessibility notes (contrast, target size, forced-colours fallbacks) as comments next to the classes or tokens they explain.

### Linting and formatting

- [Biome](https://biomejs.dev) formats and lints everything (TypeScript, Astro, CSS, JSON, Markdown). Configuration is in `biome.json`. Don't add ESLint or Prettier.
- Run `bun run check` (Biome, then `astro check` for types) before committing, and `bun run check:fix` to apply safe fixes. CI runs `biome ci` and `astro check` on pull requests and before every deploy.
- `astro check` needs TypeScript 6; keep `typescript` on `^6` until it supports 7.
- Formatting: tabs, double quotes, 120-character lines. Imports are sorted automatically.
- Tailwind classes are sorted by the `useTailwindSortedClasses` rule. Its fix is marked unsafe, so apply it with `bunx biome check --write --unsafe`. Biome doesn't read `@theme`, so classes that use custom tokens (`bg-fg`, `text-muted`, ...) sort to the front; that's expected.
- If a rule must be broken on purpose, suppress it locally with a `biome-ignore` comment that gives the reason, rather than turning the rule off.

### Site content and assets

- Personal details (name, title, email, social links) live in `src/data/profile.ts`. Read them from there; don't hard-code them in components.
- `public/og-image.png` and `public/apple-touch-icon.png` are generated by `scripts/generate-images.ts`. Run `bun run images` after changing the name, title or brand colours, and commit the PNGs.
- Brand colours are repeated in a few places that can't read CSS variables (`theme-color` meta tags, `favicon.svg`, the image script). Update them together with `@theme` in `global.css`.
